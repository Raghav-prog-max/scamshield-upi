# ScamShield UPI

Paste a suspicious SMS, WhatsApp or email message, in **English, Hindi or Hinglish**, and ScamShield tells you:

1. whether it is a **UPI / KYC / banking scam** (`scam` / `suspicious` / `safe`, with a confidence score and scam type),
2. the **red flags**, each quoted word-for-word from the message and highlighted, with a plain-language reason,
3. **what to do next**: what to do now, what never to do, and where to report it (cybercrime.gov.in / 1930), replied in the user's own language.

Built as a prompt-engineering mini project: three chained Gemini prompts (`gemini-3.1-flash-lite`, see [Model](#model)), versioned prompt files, a measured prompt-iteration history and a reproducible test runner.

- **Live demo:** <https://scamshield-upi.vercel.app>  ·  **Code:** <https://github.com/Raghav-prog-max/scamshield-upi>
- **Team members:** _Name 1 (roll no.)_, _Name 2 (roll no.)_, _Name 3 (roll no.)_ ← _replace_

## Prompt pipeline

Three distinct LLM calls, chained. Each prompt is a Markdown file in [`prompts/final/`](prompts/final/), loaded at runtime, so the files are the single source of truth. Run settings (temperature, JSON mode) live in each file's frontmatter.

| Step | File | Input variables | Output (strict JSON) | Settings |
|---|---|---|---|---|
| **P1 · Classifier** | [`P1.md`](prompts/final/P1.md) | `{message}` | `{ verdict, confidence, scam_type, language }` | temperature 0.1, `responseMimeType: application/json`, 2 few-shot examples |
| **P2 · Red-flag explainer** | [`P2.md`](prompts/final/P2.md) | `{message}` `{verdict}` `{scam_type}` | `[{ flag, evidence, why_risky }]`, or `[]` if safe | temperature 0.1, JSON mode, 2 few-shot examples, thinking off |
| **P3 · Action advisor** | [`P3.md`](prompts/final/P3.md) | `{verdict}` `{scam_type}` `{red_flags}` `{language}` | `{ summary, do_now[], never_do[], report }` in the user's language | temperature 0.2, JSON mode, thinking off |

Safeguards in code around the prompts:

- **Input validation** (browser and server): empty input and input over 2000 characters get a friendly message and **no LLM call**.
- **Strict JSON + retry:** each step's raw output must pass `JSON.parse` and the schema. If it doesn't, the step is retried once; a second failure shows a clean error.
- **Evidence grounding:** any P2 red flag whose `evidence` is not actually in the message is dropped, so the UI never shows an invented quote.
- **Prompt-injection hygiene:** the message is wrapped in `<message>` tags and every prompt says to treat it as data only. P3 never sees the raw message, so it cannot repeat a scam link.

Diagrams: [prompt workflow](docs/prompt-workflow.md) · [task decomposition](docs/task-decomposition.md) · [input → output flow](docs/input-output-flow.md) · [system architecture](docs/system-architecture.md)

### Model

The project was planned for **Gemini 2.5 Flash**. On 2026-11-22, a newly created API key got **HTTP 404** for `gemini-2.5-flash` and `gemini-2.5-flash-lite` (*"no longer available to new users"*). `gemini-3.8-flash` returned **HTTP 503** (high demand) in the same check. `gemini-3.5-flash` worked with the prompts' exact settings (temperature 0.1, JSON mode, thinking budget 0). However, its free tier allows only **20 requests per day per model** (from Google's 429 response: `GenerateRequestsPerDayPerProjectPerModel-FreeTier=20`). That limit ran out partway through the first test run, and it would allow only about 6 checks a day on the public demo, since each check makes 3 calls.

The default model is therefore **`gemini-3.1-flash-lite`**. It works with the same settings, and its free daily quota is larger: v1's 27 calls ran without hitting a daily limit. **All test results below were measured with `gemini-3.1-flash-lite`.** To use a different model, set `GEMINI_MODEL`; the prompts stay the same. Google does not publish free-tier limits per model; signed-in users can see them at <https://aistudio.google.com/rate-limit>.

### P1 iteration (v1 → v2 → v3)

| Version | What changed | File |
|---|---|---|
| v1 | Bare prompt: *"Is this message a scam? Answer yes or no and explain."* No format, default temperature. | [`prompts/v1/P1.md`](prompts/v1/P1.md) |
| v2 | + role (fraud analyst for Indian UPI/KYC scams), + fixed JSON schema, + `scam_type` categories. Still default temperature; JSON requested in words only. | [`prompts/v2/P1.md`](prompts/v2/P1.md) |
| v3 | + 2 few-shot examples, + temperature 0.1, + JSON mode, + rule *"a genuine bank alert that does not ask for OTP/PIN/link click is safe"*. | [`prompts/v3/P1.md`](prompts/v3/P1.md) |
| final | P1 = v3 unchanged, plus P2 and P3. | [`prompts/final/`](prompts/final/) |

Each version was run against the full test set by [`scripts/run-tests.ts`](scripts/run-tests.ts). The measured numbers are in **[`test-data/results-summary.md`](test-data/results-summary.md)** (generated by the script, not typed by hand). Raw model outputs are in [`test-data/outputs/`](test-data/outputs/).

Final pipeline extras:
- P2 evidence was quoted word for word in 48/48 flags.
- P2 returned `[]` for 8/8 safe runs.
- P3 replied in the user's language in 23/23 runs.
- P3's report line was correct in 23/23 runs.
- No step needed the retry (0/69).
- Average time per pipeline run was 14.7 s.

**Failures (kept, not tuned away):**
- **E5** ("friend" asking for money from a new number) was expected `suspicious`, but every version said `scam`. This is a judgement call in the test set. Both are "risky", so the risky-vs-safe accuracy counts it as correct.
- **N2 run 1 (final)** failed because Google's servers returned HTTP 504 (`DEADLINE_EXCEEDED`). The prompt itself did not fail. Run 2 of the same case passed.
- **v1 and v2** called genuine bank alerts (N5, and for v1 also N6) scams. v3's explicit bank-alert rule and its few-shot examples fixed this.

## Repository structure

```
README.md            this file
CHANGELOG.md         dated log of every change
prompts/
  v1/P1.md           bare prompt
  v2/P1.md           + role, JSON schema, categories
  v3/P1.md           + few-shot, temperature 0.1, JSON mode, bank-alert rule
  final/P1.md P2.md P3.md   the prompts the app uses
code/README.md       pointer: the app lives at the repo root (explained below)
app/                 Next.js App Router: page + /api/analyze route
components/          React UI (analyzer, result card)
lib/                 pipeline, prompt loader, Gemini client, validators
scripts/             run-tests.ts (prompt test runner), check-secrets.sh (pre-commit hook)
test-data/
  inputs.json        14 test cases (6 normal, 5 edge, 3 invalid)
  outputs/<ver>.json raw model outputs + computed metrics per version
  results-summary.md one row per version
docs/                Mermaid diagrams (.md)
```

**Why the app is at the root and not in `code/`:** Vercel deploys a Next.js app at the repository root with zero configuration, and the API route reads `prompts/final/*.md` at runtime. Those files have to be inside the deployed project, so a root-level app bundles them automatically. `code/README.md` maps every source file.

## Run locally

Requirements: Node.js 20+ and a Gemini API key from <https://aistudio.google.com/apikey>.

```powershell
git clone <your-repo-url> scamshield-upi
```

```powershell
cd scamshield-upi
```

```powershell
npm install
```

```powershell
Copy-Item .env.example .env.local
```

Open `.env.local` and put your key after `GEMINI_API_KEY=`. Then start the app:

```powershell
npm run dev
```

Open <http://localhost:3000>.

### Run the prompt tests

```powershell
npx tsx scripts/run-tests.ts --version all
```

Options: `--version v1|v2|v3|final|all`, `--runs 2` (default; each input runs twice for the consistency check), `--only N1,E5`, `--summary-only` (rebuilds `results-summary.md` from saved outputs without calling the API). The runner waits and retries when Gemini's per-minute limit is hit, and stops without saving if the daily quota runs out.

## Deploy to Vercel

Option A — GitHub import (no CLI):

1. Push this repo to GitHub (it must **not** contain `.env.local`; the pre-commit hook and `.gitignore` prevent that).
2. Go to <https://vercel.com/new>, then **Import** the repository. Vercel detects Next.js; leave Root Directory as `./` and keep the default build settings.
3. Under **Environment Variables** add `GEMINI_API_KEY` = your key (for Production, and Preview if you want).
4. Click **Deploy**. Copy the `https://<project>.vercel.app` URL into the "Live demo" line above.
5. Check that visitors don't need to log in: Project → **Settings → Deployment Protection**. **Vercel Authentication** must be **Disabled** for Production (on new projects it protects only Preview deployments by default, so the production URL is public).

Option B — Vercel CLI:

```powershell
npm i -g vercel
```

```powershell
vercel login
```

```powershell
vercel link
```

```powershell
vercel env add GEMINI_API_KEY production
```

```powershell
vercel --prod
```

Optional env var: `GEMINI_MODEL` (default `gemini-3.1-flash-lite`).

## Privacy, safety and limits

- The API key is read only from `process.env.GEMINI_API_KEY` on the server. It is never sent to the browser or committed (`.gitignore` covers `.env` and `.env*.local`; `scripts/check-secrets.sh` runs as a pre-commit hook).
- Messages are sent to Google Gemini for analysis and **not stored** by the app.
- A best-effort, in-memory rate limit (8 checks per minute per IP, per server instance) protects the API quota on the public demo.
- This is an AI prototype and can be wrong. It is not a substitute for your bank or the police. If money was lost, call **1930** immediately.
